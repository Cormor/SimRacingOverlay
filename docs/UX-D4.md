# RacingOverlay UX 重做 · D4

版本：UI-D4；2026-11-09。以1.6.5为功能基线，保留既有HUD与输入链，重组管理体验。

## 目标与范围

纠正“元素整齐但不好理解”的组织问题，不再逐句减字。用户必须能判断：我在哪、当前实际是什么、操作改变什么、何时保存、下一步在哪里。产品整体包括管理窗、设备子页、HUD与桌面入口、安装与更新；本次重做管理体验及信息呈现，HUD仍是快速观察层，保留18个组件、算法/阈值/插值/遥测/盘面厂设映射与用户布局。不给驾驶层塞说明或新装饰，也不为外观换计算链。

## 有依据的取舍

- 推翻：概览三张等权状态卡加无差别快捷键堆叠。显示HUD与编辑画面是主任务；连接事实紧邻预览，调整入口按对象排列。G峰值重置降为驾驶统计操作，不占主按钮首位。
- 保留：深浅主题语义色、44px普通热区、原生窗口行为、真实HUD预览、布局手势与Undo、所有组件/盘面/设备能力、现有下载/更新/安装安全边界。
- 简化：不把每组信息都包成大卡片，删重复标题、永远正确的提醒和非必要成功框。金色只强调当前导航、主要动作与焦点，不给每个边框套材质；材质不承担信息层级。
- 细化：正常、等待、数据停止、失败与设置草稿分开。不得把game或device合成connected当作设备已连接；不得把没有游戏数据当作程序故障。已保存、待应用与已应用各自绑定对象。
- 加强：信息顺序、说明与字段关联、固定提交位置、错误可见与回到错误位置、键盘导航、短窗口和放大后的布局。

## 依据→选择

Norman的概念模型/反馈：用户需要把意图映射到对象和结果→按布局/组件/盘面/设备组织操作，说明生效范围，不设置虚假的统一保存。Wertheimer接近性：相邻与共同区域支持分组→标签、读数、动作放在同一任务区，组内8–12px、组间24px；数值为公司工程选择，不是论文唯一结果。GOV.UK内容与错误模式：必要帮助在操作前，错误能定位到问题→保存栏不藏进最后一张设置卡、离页失败滚动到提示。W3C4.1.3：重要无焦点反馈可被辅助技术识别→异步动作结果role=status，真实阻止动作的错误role=alert；实时80ms读数不作live播报。公司tokens2.1及共享组件1.1继续作为工程基线。

来源： https://jnd.org/design-as-communication/ ；https://psychclassics.yorku.ca/Wertheimer/Forms/forms.htm ；https://design-system.service.gov.uk/components/error-summary/ ；https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html 。外部指南不证明本次已通过用户研究或安全认证。

## 信息架构与页面

导航分两组：“驾驶画面”含概览、布局编辑、组件样式、方向盘；“设置”含设备输入、显示与连接、版本与更新；支持开发为末尾次要入口。方向盘与设备分开可直达，内部仍复用同一inputs页的两个panel与同一设备保存拥有者，不另建第二份状态。保留现有navigate('inputs')兼容，默认方向盘；设备入口显式选设备panel。窄窗仍保留图标的可读名称和tooltip。

### P01 概览

头部“驾驶画面”，一行主操作“显示HUD/隐藏HUD”，邻近状态“已开启/已关闭”。主体左侧为真实“当前布局”预览与“编辑布局”主动作；右侧为“连接状态”事实列表：游戏/设备分开显示，必要指引就近。下方三个对象入口：方向盘、组件样式、设备输入；每项只一句说明实际用途。本段G峰值重置放独立次要统计行。预览画的是当前布局而非声称桌面正在显示：HUD隐藏时也可以预览。

### P02 布局编辑

保留三栏空间工具，工具条“撤销/重做/更多”，移除页面重复快捷键按钮（快捷键放可发现的工具菜单与设置）。保存状态使用单行：自动保存/保存中/已保存/保存失败与重试，完成编辑常驻右下。未选组件时显示空状态，不铺满禁用0值字段；选中才显示几何、常用透明度和动作；高级对齐/层级/复位按需展开。画布下“桌面参考”：半透明/直接编辑/不显示，各模式旁一行必要后果，解释只在用户选择模式处出现。保持现场紧凑模式、空位避让和取消语义。

### P03 组件样式

先选对象，左侧“显示效果/配色与辅助/计算方式”分组；固定能力显示只读名称，不伪装可选择控件。右侧等大“已应用/修改预览”，显式“演示数据”与“实时输入”来源切换，暂停/重播在预览旁。提交栏常驻：有改动显示“此组件有未应用修改”，主按钮“应用到［组件］”，次按钮“撤回此组件修改”；无改动不显示成功大框。其它组件草稿计数可见且可定位，不隐式应用或清空。扩展导入降为附属入口。

### P04 方向盘

正在使用的盘面与浏览选择分开，选择已安装盘面会立即切换的后果在选择字段下明确；下载未安装盘面使用“下载并使用”，失败保留当前盘面。左配置右真实画面，仪表方式与挡位方向分组，映射折叠按盘保存。不更改原异步切换拥有者或厂设。

### P05 设备输入

完整独立导航，保留iframe复用。先看真实设备与当前输入，再设置绑定。采样说明只在轴学习区域，当前轴行显示原绑定/采样/待保存，不能用“已采用”冒充已写入。转向角与轴绑定同组，旧通用按键和MOZA观察折叠为高级；保存栏独立常驻底部，显示“有未保存修改”、保存中或结果，保留必要错误。离页拒绝将保存/采样错误带入可见位置，焦点移到可处理提示，不能在底部悄悄失败。不新增自动丢弃。

### P06 显示与连接

分“桌面显示”“游戏遥测”“OBS”任务区。显示器与显隐在桌面区；游戏实时状态与接入指引在遥测区，原始能力列表在“数据详情”展开中。快捷键在次要设置区；输入格已有组合键时不另复述“当前快捷键”。OBS地址只读可选且复制按钮相邻，说明其画面与桌面显隐独立。错误显示在该操作附近，不能只写进隐藏的布局notice。

### P07 版本与更新 / P08 支持开发

更新页版本与检查动作一行，必要检查/下载/安装状态就近，完整升级影响说明紧邻安装动作；未发现可安装新版本时不展示把同版本发布说明包装成待更新的大卡。发布说明可展开阅读，本地包单列次要区域。保留现有已验证检查结果、竞态隔离、签名/域/路径与安装协议。支持页保留可扫码资源及原主题策略，只统一标题/宽度/导航，不擅改支付语义或图片。

## 状态事实与显示优先级

|对象|依据|显示|动作|
|---|---|---|---|
|游戏等待|!game.available且ui.waiting或无有效快照|等待游戏数据|进入赛道；接入说明可达，不臆断断线原因|
|游戏可用|game.available且!ui.waiting|正在接收 · 来源|查看数据详情|
|游戏等待驾驶|game.available且ui.waiting，且无已知暂停/菜单|等待驾驶数据|不臆断断流原因；保留现有HUD缺值语义|
|硬件未知|尚未取得硬件采集快照|正在读取设备|不宣称断开或已连|
|硬件无当前样本|hardware.current!==true，或ageMs非有限值/超过validForMs|设备状态暂不可用|仅显示确认事实|
|设备有效|hardware.current且采集ageMs有效未过期，新鲜devices非空|N个输入设备|设备输入设置；不推断所有都是方向盘|
|无设备|当前且未过期的硬件采样，devices为空|未检测到输入设备|连接设备或使用游戏输入|
|显隐意图|nativeState.visible（来自settings.visible）|HUD已开启/已关闭|表达已保存的显隐意图，按钮为相反动作；编辑参考与真实窗口呈现另行区分|
|保存/应用|对应拥有者实际写回结果|当前操作状态|错误优先于成功；同对象新操作撤销旧完成提示|

硬件current在现实现中只保证epoch及validForMs配置有效，不能独自证明采样新鲜；管理表现须同时使用其ageMs/validForMs。game.available也不证明驾驶场景：game.paused/inMenu为真优先显示“游戏已暂停/游戏菜单中”；ui.waiting单独为真只说“等待驾驶数据”，不能断言数据停止，因为它实际只检测来源/车辆packet是否在1500ms内前进，不区分停止原因。

状态不要把“未加载”当“空”、过期当0、设备连接当轴已绑定、包已下载当已安装。错误直到解决或被同对象新动作取代；静态就绪状态不作常驻告警。说明只有影响下一步时显示，必要范围/单位/生效方式不藏进tooltip。

## 共享组件补充约定

沿用C01–C12。新增可复用：任务入口（44px以上，标题16/说明14，整项单一动作，focus-visible）；事实行（标签14/值16，辅助14，分组内8–12/组间24，不能伪装可点）；页面标题区（h1 24，任务说明14按需，主动作靠右，窄时换行）；局部提交栏（44px按钮、内距12/16、边界1，sticky置于自身滚动容器，不覆盖最后内容，有消息才占消息空间）。选中与键盘焦点分开；标题/分组无装饰动画，沿用减弱动态；深浅主题读取同一语义令牌。

## 页面尺度和验收

设计原型：[D4可编辑页面](../design/ui-d4/index.html)，使用公开示意状态，不读用户配置，不作为实际遥测或功能验收证据。1440×960 CSS px基线，960×720紧凑与浅色/键盘态；宽度是项目工程值。布局编辑保留二维舞台，不声称舞台可在320宽直接精确操作；设置正文在窄视口可回流。原生窗口最小尺寸继续按已有平台约定。

验收必须从当前正式安装身份走通：显示/隐藏HUD；布局选择移动、撤销与保存；组件选项动态对比与应用；盘面选择/下载实际后果；设备学习取消/保存与离页提示；显示器/OBS复制；真实更新检查与本地包信息；深浅主题、短窗与键盘。真实驾驶尚未发生时不宣称实车可用性；不退出游戏或改变第三方设置。D4还须依据最终安装版画面与操作结果完成独立审查。

## 实施中的事实映射澄清

`desktop-main.js:status()`的visible来自用户settings.visible，编辑参考/透明供帧可改变实际窗口呈现。因此管理页用“HUD已开启/已关闭”表达用户显隐设置，不写“已显示”冒充实际像素。正常驾驶与编辑参考分别说明。对应控件与操作仍保持D4。
