# 组件功能、样式、动画与配色

版本 2026-11-07，当前为CX02动态比较及独立显示辅助退修。可编辑页面图源：[selection.svg](../design/component-experience/selection.svg)。

## 用户任务与依据

用户要在保留当前赛车指标和布局的情况下选择某组件的功能定义，再独立决定显示样式、动画、配色及显示辅助。全部现有布局组件均在目录中展示，包括固定算法/样式组件；首批可替换功能是 HUD 的 `throttle` 与 `brake`。收油是油门指示的状态，不另造一份踏板或数据来源。算法负责踏板响应含义，表现消费语义结果，动画消费表现状态，配色只改颜色；显示辅助显式添加读数、符号或底板，保留所选样式和动画。

沿用公司 design/design-basis.md 已收录的 Norman 概念模型和反馈依据：五种作用分别命名并就近解释，用户能把选项和结果对应；当前配置与未应用草稿分开，避免误认草稿已生效。Wertheimer 接近分组用于将同一组件的五种选择置于同一卡片，减少在多设置页来回寻找。Fitts 原则支持保留已有44 CSS px操作目标和整行选择器；44px为公司工程取值，不是理论唯一结论。现有 UI-COMPONENTS Select、导航、卡片、按钮、状态提示直接复用。页面继续使用 ui-tokens.css 的黑金/白金令牌，不改布局画布的指示色义。

## 最少操作路径

侧栏“组件与动画”→选择任一现有组件→调整功能算法/显示样式/动画/配色/显示辅助→“应用到此组件”。布局单选这些组件时，属性栏的“功能与动画…”直接带入所选组件。五个选择独立，允许同算法不同样式/动画/配色，也允许不同算法共用样式；组合是否兼容由契约判断，不声称任意组合可用。

草稿按组件保存在本次管理窗口会话内，切组件和离页保留。应用只提交当前组件变更，并以最新目录中的其他组件已生效值为基础，避免把其他组件草稿一并保存。点击“撤销选择”恢复当前组件已生效值。应用失败保留全部草稿和原HUD，显示原因；成功后才更改“已应用”说明，HUD重载由宿主处理。应用前沿现有路径完成布局保存；保存失败不执行配置切换。

## 关键状态与预览

载入中禁用选择和应用；目录读取失败展示可重试原因。兼容组合显示可用，不兼容组合展示具体原因并禁止应用；可用选项保留说明，无法单独使用的选项带兼容原因。需要同时改多维的选项仍可选，组合不可用时禁用应用，避免合法新组合因中间步骤不兼容而无法组成。仅目录明确禁用的选项灰置。选项变化不改变正式HUD。两块等尺寸canvas并排显示“当前”与“预览”，输入和时间完全相同，复用真实组件渲染器。演示按当前组件用途提供持续有效的代表性输入，不让油门/刹车长时间轮流空白，不让手刹只在周期末端短暂非零；来源选择标明“演示”，实时无数据时另提示已切为演示数据，不把演示状态写入遥测或运行配置。用户在没有游戏数据时也能看到差异。暂停冻结统一演示时间，改选项仍立即重绘草稿；从头演示清两侧预览历史并将演示时间归零，播放/暂停状态保留。离页/最小化停止帧调度，返回以暂停前演示时间继续，不累计后台时长；卸载释放预览实例。预览错误就近显示，不假装成功也不影响正式HUD。

固定算法、样式或动画的选择器仍展示名称和说明，但单项时禁选、字段名只标一次“固定”；固定能力并不隐藏组件。所有组件均能选择“标准 / 色弱配色 / 高对比配色”三类纯配色。色弱配色展开第二个选择器：红色辨识困难（Protan）、绿色辨识困难（Deutan）、蓝黄色辨识困难（Tritan）；提示按预览选择，类型名用于配色偏好，不作诊断。各类型继续存入既有theme字段中的独立ID，且只改变颜色，不改变形态、线型、底板、标注或动画。独立的“显示辅助”选择为“标准 · 无额外辅助 / 色弱显示辅助 / 高对比显示辅助”，分别保存assistance=none/colorblind/contrast；色弱辅助叠加非颜色读数及符号，高对比辅助只在必要图元或文字处加紧贴的字底和稳定标记，遵守原组件显隐，但保留已选presentation的线型及animation。辅助不是覆盖显示样式的模板，配色与辅助不会相互联动。

动态默认即时；可选动态须帮助辨认该组件的输入跟随或状态变化，不以外围循环、扫描边框或无业务含义进度条凑数，也不改变测量值和算法含义。系统减少动态优先，动画选择仍保存，运行端即时显示目标；页面用文字说明当前系统偏好。配色独立于管理窗口深浅主题，默认沿用仪表语义色；白金配色仍保留警告/危险颜色含义。

本地组件包入口复用“版本与更新”的导入与内容确认流程。包含执行代码时明确指出；导入/应用后重取组件目录，未知或失效草稿不自动应用。更新页既有官方更新、hotfix与盘面包流程保留。

## 几何与交互

桌面宽窗口采用选项卡片和动态比较两栏，最小列宽约280px；不足宽度依现有1199px断点转单栏。卡片24px内边距、字段16px下间距、44px最小目标沿现有定义。选择器采用既有UIControls.Select，保留Tab、上下键、Enter、Esc及禁用语义；状态role=status、错误role=alert。应用期间禁用选择/撤销/应用避免中途换组件，业务状态不依赖动画结束。

## 对接边界

管理页只消费宿主组件目录和配置接口；组件schema、算法兼容、保存与HUD重新载入由组件核心负责，原布局编辑/撤销仍由管理器持有。目录刷新须带代次，过期响应不得替换新目录或草稿；提交期间不接收第二次应用。正式接口为`components()`读取目录，含revision、各组件selection和compatibility组合矩阵；`applyComponents({selection,revision})`拒绝旧目录，失败保留草稿。管理页只按矩阵显示兼容性，不装载包内可执行脚本。


## CX02导航及比较布局依据

用户截图显示更新项使用字体箭头、其他项使用SVG，因此首槽宽度和基线随字形变化。统一六个导航项的24×24 CSS px槽，内含20×20 SVG、16×16 viewBox、1.5单位笔画，display:flex居中，标签与槽间12px。组件图标用模块形状及播放三角区分布局；更新为上传箭头及底托。图标几何是本项目工程选择，沿公司统一图标规范；不再依赖字体箭头。

并排比较沿用受控比较原则：其他条件相同时才可把可见差异归于选项，因此两侧等尺寸、同演示输入、同时间，变化仅来自选择。暂停后改样式仍重绘，避免把“暂停输入”误成“暂停全部反馈”。这替换了CX01只显示当前HUD的不足；原方案无法预览未应用草稿，不能满足实时比较。


CX02预览接口：`host.createComponentPreview()`返回`draw(ctx,{component,selection,time,width,height,source})/reset()/dispose()`；左右独立controller，共用每帧毫秒time。来源可选“演示”与“实时”，实际来源标签取draw返回结果。主题目录以family=standard/colorblind/contrast分组，色弱type=protan/deutan/tritan；配色仍持久化为单个theme ID；显示辅助单独存储assistance。


## 配色、形态与显示辅助的独立边界（2026-11-07退修）

此前将线型、实底和标注随色弱/高对比主题一起切换，使用户只改配色却改变显示样式。当前将职责落实为：功能算法定义语义，presentation定义形态，animation定义动态，theme只定义颜色；assistance显式叠加非颜色识别辅助，不覆盖所选形态或动态。界面各选择事件只更新自己的字段；例如分段样式、即时动画、Tritan配色在改配色或改辅助时均保留其他已选值。

最小迁移保留schema/apiVersion和原四轴ID，只新增可选assistance字段。缺字段一律补none，不从色弱或高对比theme推断辅助；不自动写其他轴，不恢复内置baseline。compatibility矩阵继续定义原四轴组合，assistance由catalog.assistances独立列举及校验，所有组件支持三值。草稿差异按字段比较，避免补字段顺序造成虚假改动。安装切换前由唯一安装者只读取得最新18项草稿并恢复；管理器不为保全而新增应用动作或清空草稿。

CX02图源保留当时四轴布局；本次辅助选择器复用同卡片既有字段几何，当前字段及职责以上述五轴定义为准。


## 按组件用途收敛与扫读整改（2026-11-07）

实际current-manager.png显示：固定算法说明重复同一句，选项与多段架构解释反复出现；仪表在强制方形画布中上下留白很大。原演示又让油门和刹车按6.4秒交替，手刹仅周期末400毫秒出现，造成长时间看不到所选组件有效变化。这些是样本和页面信息取舍的问题，不能用增加动画数量、说明或只缩小画布替代。

配置页只保留选择所需信息：算法/样式/动态/辅助/配色名称，以及所选能力的一句差别；固定能力在字段标题标一次“固定”。已有上下文的默认选项只写“默认”，真实差异才使用短名称；不展示“现有固定算法”“原有组件形态”“复用当前原始绘制”或旧ID兼容等实现身份，不把capabilityNote与description叠加，不拼接五轴已应用长句。正常状态为“已应用/待应用”，错误保留具体原因；普通动态偏好不另说明，仅系统减少动态生效时提示。当前/预览两侧标题明确，来源以“演示/实时”在选择器出现一次，正常draw返回的工程标签不重复铺在画布下。包与协议细节留维护文档。

选择组件后立即进入该组件有代表性的连续有效演示，不要求先点场景。真正有助于理解算法或样式差异时才提供紧凑场景选择，场景输入经原算法处理，不直接注入告警语义。动画只服务输入跟随、状态变化等用途；无意义外围边框扫描和进度条不作为丰富度。固定能力照实展示，不为凑选项给所有组件套通用动效。辅助在原显示样式的锚点增加必要标记，不把细条或短提示包成大卡片，不改变原有显隐含义。实际能力及演示场景由组件核心目录定义。

左右画布始终同尺寸同输入。其比例取所选组件的既有layout.bounds，约束到1至3、最小高160 CSS px：仪表/横条用横向画布，方向盘和G球近方形。这是面向可读性的工程取值，不修改HUD本体；仅随组件切换固定，不逐帧按样式内容auto-fit，因此对比缩放不随选项变化。该布局改善只减少空间留白，时间空窗仍由前述代表性连续输入解决。

选择另一组件（含布局属性直达）会将两侧预览历史及时间归零，保持播放/暂停状态和全部草稿；改变同一组件的配色、样式等选项不重置时间。核心须在新组件time=0就提供代表性有效输入历史，暂停切组件也无需等待。

全管理窗同类文案已按概览、布局、盘面、连接、更新路径收敛：布局对象统一称组件；连接能力仅按源码已声明布尔字段展示功能名及“提供/未提供”，不将未知key、JSON、kinematicsProfile配置放主界面；更新用“发布说明/版本”，保留可执行代码、刷新、关闭程序、停用本地包等影响选择的后果。保存及切盘失败仍保留具体原因与原选择。

旧动态ID只作兼容数据保留，不作为日常选项丰富度：componentResult仍查完整目录；正常选择器只列非deprecated项；若当前草稿选中旧项，则只显示该原ID对应“默认”，隐藏其replacement，避免两个相同默认行为。读取、显示与预览均不改旧草稿ID，也不自动保存。
