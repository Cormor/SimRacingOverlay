# 组件显示辅助约定

2026-11-07；用于组件配色、显式显示辅助、真实 HUD 渲染与组件页并排预览。本文定义实现选择及依据，不代表整款桌面覆盖层已经通过 WCAG 验收。配色数值是项目工程起点，个人辨识效果仍由用户选择。

## 每组件的三套显示

所有可展示组件至少提供“标准（当前）”“色弱辅助”“高对比”显示辅助模式。标准默认保留当前组件的仪表语义及外观，不为补齐辅助模式而强行新增标记或重画；已有文字、方向和图例继续保留。Protan、Deutan、Tritan 是独立配色选项；色弱显示辅助提供共同的非颜色标记，没有依据为三类色觉偏好制造三份相同形态。高对比辅助仅为实际文字添加紧贴字形区域的字底，不生成通用整框或外部标题。显示辅助不修改算法、阈值、原始数据、单位、有效期和未知状态。当前已选方案与草稿使用同一时刻、同一输入分别绘制，预览必须调用实际组件绘制路径。

配色与显示辅助分开选择和持久化：`theme/palette` 只改变颜色值；`presentation` 控制组件原有几何、分段、线宽和实线/虚线等样式，也包含整体轮廓及临时显隐语义。切换配色不能清除分段虚线、改变已有线型、增加底板或添加文字。显示辅助只能依附实际数值、状态和原图元锚点添加必要表达，不能按布局编辑边界画整框、整底或外部标题，也不能让原本无提示的组件变成常驻提示牌。`framed`、`labelled` 等形态只在其显示样式被选中时采用。用户启用色弱/高对比辅助与选择某组颜色是两项明确操作；任何纯配色方案都不能单独承诺已经补齐非颜色信息。

选择字段为 `selection.assistance = 'none' | 'colorblind' | 'contrast'`。旧配置或草稿缺失时仅补 `none`，不根据 `theme` 自动启用辅助；读取不写盘，已有算法、显示样式、动画、配色选择保持原值。色弱辅助依附原图元增加非颜色标记，高对比辅助只在实际文字处提供紧贴字底及稳定可见读数；辅助不自动改配色，也不覆盖用户选择的分段线型或动画。手刹、操控提示等原实现当前不可见时不生成辅助。

色弱配色按语义角色替换颜色；显式色弱辅助模式补充可见的非颜色表达，同时保留显示样式已有的线型、方向与形状。避免对整幅画面加颜色滤镜：滤镜不能补足缺失的含义，还会同时改变正文、照片与实物盘面的颜色。照片、物理灯光采集颜色与真实设备状态作为事实保留；可以通过显示辅助增加旁侧标记，不能改写成另一项事实。

界面选择文案：

| 字段 | 可见文案 |
| --- | --- |
| 配色 | 标准（当前） / 色弱配色（按类型选择） / 高对比配色；仅改变颜色 |
| 显示辅助 | 标准（当前） / 色弱辅助 / 高对比 |
| 色弱配色类型 | 红色辨识困难（Protan） / 绿色辨识困难（Deutan） / 蓝黄色辨识困难（Tritan） |
| 类型说明 | 按预览中的文字、线型和颜色辨识效果选择。类型名用于配色偏好，不作诊断。 |
| 动态 | 跟随系统 / 减少动态；原有动画选择仍独立保留 |

Protan 与 Deutan 都涉及红绿辨识，但具体表现并不完全相同；Tritan 涉及的混淆也不能概括成单纯“看不见蓝色”。NEI 分别说明红绿、蓝黄和完全色觉缺陷，并列出其不同表现。因此界面保留独立选择，不能仅提供一个笼统“色盲滤镜”。本项目不据此诊断用户，也不声称某组颜色对同类型所有人都有效。[NEI 类型说明](https://www.nei.nih.gov/eye-health-information/eye-conditions-and-diseases/color-blindness/types-color-vision-deficiency)

## 语义令牌与工程取值

沿用公司 `SoftwareCompany/design/tokens.json` v2.1.0、`components.md` v1.1 的语义角色。管理窗继续采用公司深浅主题；以下是覆盖层组件的深色局部表面取值，不把这组亮色直接搬到白底小字。`surface` 只定义已有表面的颜色，不能由配色创建新表面；高对比显示辅助的实色背景限于紧贴实际文字的字底，不扩大为组件背板。

| 角色 | 标准参考 | Protan 起点 | Deutan 起点 | Tritan 起点 | 高对比起点 |
| --- | --- | --- | --- | --- | --- |
| `surface` | 当前组件背景；新表面 `#191B1D` | `#191B1D` | `#191B1D` | `#191B1D` | `#000000` |
| `text` | `#F4F1E8` | `#F4F1E8` | `#F4F1E8` | `#F4F1E8` | `#FFFFFF` |
| `textMuted` | `#B7B0A3` | `#C8C8C8` | `#C8C8C8` | `#C8C8C8` | `#FFFFFF` |
| `normal` | 当前语义色；新定义参考 `#72D6A4` | `#74C8FF` | `#8CCBFF` | `#72D6A4` | `#FFFFFF` |
| `caution` | 当前语义色；新定义参考 `#FFD27A` | `#FFD27A` | `#FFE08A` | `#FFB8CC` | `#FFFF00` |
| `danger` | 当前语义色；新定义参考 `#FF8F86` | `#F6B7E3` | `#FFABE1` | `#FFFFFF` | `#FFFFFF` |
| `boundary` | 必要边界按实际相邻色定义 | `#C8C8C8` | `#C8C8C8` | `#C8C8C8` | `#FFFFFF` |
| `series1/2/3` | 当前数据系列映射 | `#74C8FF / #FFD27A / #F6B7E3` | `#8CCBFF / #FFE08A / #FFABE1` | `#72D6A4 / #FFB8CC / #FFFFFF` | `#FFFFFF / #FFFF00 / #FFFFFF` |

`normal/caution/danger` 是呈现角色，不能自行产生“安全/危险”的业务结论。特别是踏板观察器的 `response-increasing / response-decreasing / response-plateau / sustained-slip`，应显示“响应增加 ↑ / 响应减少 ↓ / 响应持平 ＝ / 持续滑移 !”，不能把响应增加解释为安全、响应减少一概解释为危险。已有算法定义实际警告时保留原警告名称与严重级别。

系列身份与严重级别分开：`series1/2/3` 只提供颜色，固定图例、名称和线型由显示样式定义；不要让“第三个系列”自动表示危险。需要新增非颜色编码时，标记依附实际数据点、前后端点等原图元锚点，保留原样式已有实线/长虚线/点划线，不通过通用底板扩大细条或数据点的整体轮廓。这些辅助形态不能写入纯配色令牌。新增可访问呈现默认绘制线宽不小于 2 CSS px，是本项目起点，按组件缩放后的实际可见线条判断，不能当作 WCAG 规定，也不要求配色或辅助覆盖原样式线宽。

这些色值尚不构成实际组件对比度通过记录。标准模式允许保留原外观，但新辅助模式在定义的参考背景、默认不透明度与默认布局尺寸下，关键正文采用普通文本至少 4.5:1、必要图形/控件状态与相邻颜色至少 3:1 的工程底线。高对比正文以 7:1 为项目目标。用户可调透明度、背景/照片与布局尺寸继续保留；不据这组令牌声称任意自定义组合都达到同一对比度。透明底、渐变、叠色、动画透明度与管理页白底都需纳入实际组合；单个十六进制色值不能证明最终可读性。实际画面与模拟结论须带当时配置范围。[文本最低对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文本对比](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

## 非颜色编码覆盖

标准显示辅助模式保留已有编码与含义；显式色弱辅助、高对比及新增的可访问呈现依附实际图元补齐下表中的非颜色表达，同时保留组件整体轮廓与原显隐条件。纯配色切换不承担添加形态的职责，也不能删除已有编码。高对比即使两状态同为白色，也必须可分辨。表中要求不等于原标准外观已经通过无障碍验收。

| 组件信息 | 持续可见的辅助表达 |
| --- | --- |
| 数值、踏板、转速、速度、档位 | 保留实际名称、数值、单位、量程和当前位置；档位保留字形；踏板在真实响应标记 `responseTag` 处表达上述箭头/等号/感叹号，不另造外部标题。告警条不能仅换色。 |
| 逐轮滑移、轮胎/载荷、卸载 | FL/FR/RL/RR 或明确中文轮位；正负号/方向、量程刻度；未知显示“—/未知”，有效零显示 0；卸载使用独立标记。 |
| 前后轴、转向、底盘响应 | 前/后、左/右或方向箭头依附细条前后端点等真实锚点；保留中心线及原提示可见条件；无操控提示时不生成辅助牌。 |
| G 力球、减速度与历史曲线 | 保留实际轴向、中心/零点、图例与线型；G 力球标记附着实际数据点，不按编辑边界添加整卡或外部标题。 |
| 旗语与竞争状态 | 保留实际协议旗帜种类；加可读旗名/图案（如方格），不把蓝旗换成“蓝色盲区状态”。 |
| 设备、遥测、连接与数据新鲜度 | 在线/断开/未确认/过期文字或明确符号；保留设备名及真实能力，不能由主题增加已连接或有效状态。 |
| 盘面/图片及其他组合组件 | 原始图片保留；可读数值、方向与状态提示独立绘制。多子元素分别消费语义令牌，不能只给最外边框换色。 |

显示辅助与新增可访问呈现的文字应在当前组件或对应图例可见，不能仅藏在鼠标提示、屏幕阅读器标签或另一个设置页。新增分段样式若声明提供状态文字，实际绘制必须包含这些文字。W3C 1.4.1 要求可见的信息不只依赖颜色，屏幕阅读器文本不能单独替代可见辅助表达。[颜色使用](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)

## 动态与绘制边界

减少动态时，位移、缩放、呼吸、辉光与装饰脉冲停止；目标数值、输入位置和警告即时显示，遥测采样继续。系统偏好在运行中变化也应立即采用。警告含义不能靠闪烁频率才能区分。

关键正文、警告图形、中心/零点和必要边界使用稳定不透明层。动画只作用于可去除的装饰层，不能对整个组件统一降低 `globalAlpha`，尤其不能让高对比模式的正文随呼吸变暗。配色、显示样式、显示辅助、动画和算法分别选择；切换配色或显示辅助不清空观察历史或改变事件有效期。

公司采用尊重 `prefers-reduced-motion` 的产品基线；WCAG 2.3.3 是 AAA 的交互动画条款，不能把它称作所有遥测动画都受约束的 AA 条文。[交互动画说明](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)

## 最小有区分价值的后续验收

以下是实现首次完成后可采用的对照方法，不新增自动测试平台；实际执行仍按项目验证触发规则与当前授权判断：

1. 从 18 项实际组件中复核配色与显示辅助各自的消费路径，重点看多子元素、真实原生绘制桥、图片与组合组件；配色切换保留分段虚线与已有样式，必要形态由显式显示辅助提供，不能以目录中存在三项选项代替覆盖。
2. 使用同一输入同时显示当前方案/草稿，选择能区分正常、变化、警告与未知的现有样本；静态颜色卡不足以判断算法输出与真实绘制是否对应。
3. 对采用的实际文字/背景和必要图形组合计算对比度；透明底与动画最暗时刻纳入判断。高对比紧贴字底仅控制实际文字所在区域的背景，不据此宣称整个组件已隔离游戏背景。
4. 视已有工具能力对 Protan/Deutan/Tritan 和灰度做一次有针对性的模拟观察，看标记、线型和状态文字是否仍成立；模拟只证明该模拟条件下的结果，不证明某个用户本人适用。真实偏好由用户在预览与驾驶环境选择。

本文为设计约定；源码采用情况、真实画面结果和独立审查结论分别记录，不把建议写成已经验收。
