## iRacing 接入

直接只读打开 SDK 映射，按变量表中的名称、类型、单位、偏移和数量读取。映射和变量表复用；未运行时每秒重试一次。缓冲区选择、复制和复制后复核依据 SDK 定义的帧号与环形布局。协议依据为 [iRacing SDK 原始头文件](https://github.com/vipoo/irsdk/blob/master/irsdk_defines.h) 和 [原始客户端](https://github.com/vipoo/irsdk/blob/master/irsdk_client.cpp)。

| 输入 | 统一输出 |
| --- | --- |
| `SessionTime`（s）、缓冲 tick | 生产者毫秒时间、唯一帧号；重复 tick 不刷新新鲜度，400 ms 后退出当前来源 |
| `Speed`（m/s）、`RPM`、`Gear` | km/h、原始转速、-1/R 与 0/N 挡位 |
| `Throttle`、`Brake`（0–1） | 对应踏板读数 |
| `Clutch`（0 脱开、1 接合） | 反向转换为踏板行程 |
| `VelocityX/Y/Z`（m/s） | 车身前/左/上转为统一右/上/前；不作为世界速度使用 |
| `LatAccel/VertAccel/LongAccel`（m/s²） | 按方向转换并除以标准重力加速度，作为报告的车身 G；这些字段含重力分量 |
| `SteeringWheelAngle`（rad） | 转为统一右转为正的方向盘角；未连接输入设备时可显示此读数，不冒充前轮转角 |
| `IsOnTrack`、`IsReplayPlaying` | 驾驶/菜单与停止状态；本次支持与验证范围为驾驶遥测，不承诺回放适配 |
| `BrakeABSactive`（有效 bool 时） | 真实 ABS 触发；未提供的 TC/ESC 触发保留缺失 |

字段名称、单位和含义另与 [SDK 采集的变量描述表](https://github.com/apihlaja/node-irsdk/blob/master/sample-data/telemetry-desc.json) 交叉核对；iRacing 官方的 [ATLAS 遥测说明](https://ir-core-sites.iracing.com/dev/atlas/atlas_quickstart.pdf) 说明记录文件与参数的使用方式。实时列表由当前映射决定，不把旧表当作所有车辆均提供字段的承诺。

未提供逐轮滑移率、逐轮角度或轮胎力时保留缺失，横条按上述能力降级。Optional 字段的单位不匹配只影响该字段；驾驶/暂停标志缺失时保留 null，不宣称正在驾驶或已解除暂停。核心速度/采样时间无效时不发布有效原生快照。复制途中发现帧被改写时，保留尚在新鲜期内的上一份一致快照，不将被改写内容交给算法。会话、来源与时间回退沿现有上下文隔离历史。

## 性能实现与取舍

- 绘制继续使用浏览器 `requestAnimationFrame`，没有全局 60 FPS 上限。
- 单画布按组件记录内容与布局变化，保留未受影响的像素。改变时清理旧、新区域，并按层级重画相交组件；整体移动、缩放、透明度与重叠都参与失效判断。阴影和旋转边界有独立余量，编辑模式沿用完整绘制。
- 移除轮询与绘制对同一遥测帧的重复处理；重复帧在深度整理之前返回。G 球在采集节奏更新，绘制直接消费结果。
- 遥测优先通过 `/events` 持久事件流推送。所有查看端共用一个目标 60 Hz 的生产者和一次编码；没有查看端时暂停采集。慢客户端只取最新帧，不积攒历史队列。
- 浏览器处理队列只有一个执行中快照和一个最新待处理快照。事件流断开、无效或静默超过 400 ms 时使用 HTTP，恢复后停止 HTTP 拉取；迟到的旧请求不能覆盖恢复后的事件流。HTTP 有 1.5 秒截止时间，按目标 60 Hz 周期扣除请求与处理时间，无重叠请求。缓慢环境色以约 30 Hz 更新，其他组件在数据变化时更新。
- 轻量算法直接执行；至少观察 60 次、指数平均成本超过 1.5 ms 后迁移到 Worker。Worker 一次仅处理一个快照；错误或 1 秒超时后回到直接处理。当前模拟模型通常约 0.1 ms，常驻 Worker 的复制开销会增加占用，因此按实际负载选择。
- 原生字典快照直接传递，省去桥接内的一次 JSON 编码/解码；有效原生来源存在时降低 SimHub 备用 HTTP 的采集负担。来源选择与动态字段隔离保持不变。
- 桥接的 JSON 编码器按线程独立持有；原生来源选择串行化，避免事件流生产者与备用 HTTP 并发读取时互相影响。
- 轮盘 SVG 按当前像素密度预栅格化，只保留一份像素预算不超过 8M（RGBA 约 32 MiB）的缓存；旋转复用，缩放/DPI 改变时重建，极端放大回到矢量绘制。屏幕方向的阴影仍由原画布绘制。16 个转速灯轮廓复用 `Path2D`；仪表只有数字或转速条实际改变时重画。默认不透明组件直接绘图，省去每次绘图前后重复设置透明度，半透明及异常恢复路径保持原有行为。

试验过多画布分层；本机动态基准中其 CPU 更高，因此最终采用单画布局部重绘。按钮环境光使用局部径向光晕，减少逐按钮模糊绘制。

## 数据、显示状态与绘制的独立时钟

- 遥测接入负责算法和 G 力采样；一份输入只调用一次模型。模型计算完成后准备显示状态、组件内容指纹、布局几何和绘图任务。
- `requestAnimationFrame` 只提交最新准备好的场景，只做转向显示插值与绘制，不读取遥测、不运行模型、不重新生成组件任务。待绘制场景只保留最新的一份；显示速度低于输入速度时合并中间显示状态。
- 无新输入时，独立的约 30 Hz 时钟维护缓慢灯效、80 ms 抱死门限、指示灯保持、数据过期和 G 力历史过期。正常高频输入会合并这次装饰更新，避免两个时钟重复整理场景。
- 保持屏幕刷新时钟；内容、布局和显示角度均未变化时保留像素；相同布局的编辑器轮询不会触发重绘。布局、选择框、窗口尺寸或轮盘素材完成加载会主动失效。
- 组件按改变的区域清除并按层级重画相交对象；轮盘使用覆盖整圈旋转和阴影的局部范围，避免把整幅舞台作为轮盘失效区。
- 演示输入也有独立采样时钟，绘制回调不生产演示遥测。

`node src/test_render_clocks.js` 使用固定 60 份输入，分别以 30/60/144/240 Hz 提交显示回调：四种情况下模型均调用 60 次，场景准备均为 60 次加启动一次；较慢显示时钟合并待绘制场景。另覆盖稳定内容复用、独立过期、恢复、抱死和无遥测时的布局变化。若相邻私有工程存在，也对其前端执行相同检查。

### 基准结果与范围

算法基准用相同 VM 加载旧、新 `assist.js`，各预热后交替运行 4 轮；每轮 60,000 次消费、15,000 个唯一帧，模拟 60 Hz 遥测被 240 Hz 消费。CPU 中位数及各轮结果见 `build/renderer-test/model-results.json`，可用 `node tools/benchmark-model.cjs` 重现。此次 CPU 时间约下降 67%。

Electron 基准使用隐藏窗口和统一模拟刷新时钟，分别测试目标 60/144 Hz、目标输入 60 Hz；旧版仅对齐轮询目标周期，算法和完整绘制保持旧实现。CPU 为 Electron 返回的渲染进程平均占用（含该进程的 Worker），绘制数是 4 次约 1 秒采样期间的调用次数，并非实车屏幕帧率。当前版本采用事件流，旧版采用 HTTP 拉取；表中单独记录实际处理量。

| 时钟拆分前的历史测试 | 旧实现 → 当时实现 CPU | 绘制调用数 | 处理快照数 |
| --- | --- | --- | --- |
| 控件状态稳定，目标 144 Hz | 0.698% → 0.390%，约下降 44% | 454 → 568 | 172 → 241 |
| 持续转向与逐轮滑移变化，目标 60 Hz | 0.670% → 0.588%，约下降 12% | 220 → 230 | 197 → 242 |
| 持续转向与逐轮滑移变化，目标 144 Hz | 0.719% → 0.736%，约增加 2.3% | 365 → 520（约增加 42%） | 132 → 241（约增加 83%） |

上表保留时钟拆分前的测量记录；当前架构以本节后续时钟拆分结果为准。数据来自受控输入下的渲染进程测试。真实 iRacing 驾驶、具体车辆字段、实时采样频率、方向盘驱动与整机占用仍需现场记录。只读检查当前本机仅有 iRacingService64，SDK 映射不存在（build/sdk-readback.json）；已编译运行组件包含新事件流模块。未启动游戏或操作方向盘。

重现渲染验证：用项目 Electron 运行 `tools/test-renderer.cjs --hz=144 --steady` 或去掉 `--steady`，也可使用 `--hz=60`。结果按场景写入 `build/renderer-test/results-<频率>-*.json`，截图同目录。`--pixels-only` 只执行像素对照；`--perf-only` 只执行基准；`--recovery-only` 验证真实浏览器的传输恢复；先运行遥测 C# 检查后，`--native-only` 验证原生事件流的浏览器消费。`--profile` 额外生成 CPU 采样文件，其占用结果包含采样开销。

诊断接口 `overlayDiagnostics.getPerformance()` 返回处理模式、`transport`、接收事件帧数和合并帧数；兼容字段 `polls` 现在统计处理快照数，`network` 仅统计被采用的 HTTP 备用响应开销，不表示事件流网络延迟。`getPaint()` 返回实际绘图/复用次数。

### 当前转向响应与车身失稳（lateral-response-v14，2026-10-24）

- 主判据使用当前速度、方向盘转角、横摆角速度、车身速度方向及其短时变化；反打、过去好圈、车手习惯或经验抓地峰值均不是识别前提。
- 有有效前轮角及轴距时直接使用；否则按有出处的转向传动比转换方向盘角度。中性参考为 `r₀ = v_forward / wheelbase * tan(roadWheelAngle)`，实际车头横摆率与轨迹方向变化 `r_path = yawRate + betaRate` 分别比较。120 ms 局部导数和最多 100 ms 的正横摆加速度投影用于普通入弯瞬态，初次入弯最初 100 ms 响应尚未建立时显示未知。
- 前条反映相对中性几何的当前转向跟随偏差；小车身侧滑角不再保证前条满绿。后条根据车头与速度轨迹分离、外向侧滑及其增长反映后轴失稳；有效残差反复换向产生独立侧摆状态。横条不添加文字。
- 这些条是归一化的响应/失稳指标，不是轮胎剩余摩擦力的实测百分比，也不能据此把所有稳定欠转向归因于轮胎已达到峰值。逐轮力、载荷和滑移缺失仍为 null，不将同轴车身观测伪造为四个独立测量值。
- 当前 GR86 仅在活动车手的 `CarPath=toyotagr86` 且 `CarID=160` 同时匹配时附带名义几何：轴距 2.575 m，转向比 13.5；后者来自量产车资料，尚非 SDK 报告的赛车转向比。模型记录其名义来源并留 8% 参考容差（工程容差，非测得误差界）。未知车型不套用此参数，不学习过去的驾驶当默认几何。几何缺失影响前轴参考，已明显增长的车身失稳仍可单独识别。
- 来源：[iRacing GR86 手册](https://s100.iracing.com/wp-content/uploads/2024/09/Toyota_GR86_Manual_V2.pdf)、[Toyota GR86 技术资料](https://pressroom.toyota.com/all-new-2022-toyota-gr-86-thrills-around-every-corner/)。[iRacing/Cosworth 的中性横摆比较方法](https://www.iracing.com/cosworth-pi-toolbox-plus-free-trial-returns-updated-features-for-iracing-spa-24/)提供方法依据；该产品支持名单不作为本工具 GR86 几何已实测的证据。
- SDK 适配新增右正横摆/俯仰角速度、方向盘轴扭矩、姿态、四轮减振器位移/速度与路肩声音频率。减振器位移不当作轮荷，扭矩不当作轮胎力。EngineWarnings/SessionFlags 按 bitfield 类型读取；熄火、限速、水温、油压、燃油压力及离轨接入已有状态区域。TC/ESC 触发没有有效字段时保持未知，不以设置值替代。

### 输入响应复审修正（input-response-v15，2026-10-24）

先枚举当前游戏完整字段表及其 type/count/countAsTime/unit，再选择输入和运算。当前 GR86 会话共 331 项，速度、角速度、加速度、悬架等时间数组每帧含 6 点。90 秒/5377 帧原始记录中所核对的标量均等于同帧时间数组末项；赛车索引数组与时间数组分别处理。

- 直行与微小修正：保留有效运动学输入，不再因绝对中性横摆率低于 0.035 rad/s 就输出前轴未知。严重度同时使用绝对道路转角残差的平滑幅度权重，避免仅由小分母比率产生满幅警报；0.035 rad 是指标的幅度尺度，不是轮胎实测峰值。
- 纵横分离：入弯短时投影改用横摆率/前向速度的曲率变化，去掉纯纵向加减速带来的横摆率导数分量。挡位、离合、油门变化本身不触发横向折扣；真实车身横向运动改变仍正常反映。
- 验证：16 组车速/正常响应延迟组合，直行修正无推头警报且前轴连续有效；相同曲率的正/负纵向加速度输出一致；仅改挡位/离合/油门时横向输出及 handling 完全相同。已有推头、甩尾、侧摆、原生力响应及缺失隔离测试继续通过。
- 逐轮离地：当前实时变量表未发现逐轮接触布尔值或法向轮荷；PlayerTrackSurface 是本车赛道区域，CarIdxTrackSurface[64] 是逐车区域，均不是四轮接地。shockDefl/shockVel 保持其悬架物理意义，不直接赋成接地真值；当前逐轮卸载仍只由已有有效轮荷等受支持证据驱动。

- 车辆身份从当前 `DriverInfo.DriverCarIdx` 对应的 Drivers 项读取并以 `vehicleIdentity` 输出，含 carPath/carId/driverCarIdx。车型参数只对实际匹配的身份生效，不将 GR86 当默认值；换车、未知车或元数据修订不完整时先清除旧几何。切换活动车、混合车阵、CarPath/CarID 单项不匹配及元数据读取中变化均有夹具覆盖。
