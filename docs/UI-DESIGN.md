# RacingOverlay 正式UI设计与实施契约

设计版本：UI-D3 / 2026-11-03。用户要求出正式设计图、补齐控件规范与缺页后交程序员开始修改；仅UI与交互，完整保留核心指示和算法准备。

本版定义先行输入为 [UI-COMPONENTS.md](UI-COMPONENTS.md)。旧v1/v2方向图不作为本次像素与状态实现依据。正式页面源、SVG和PNG在 `design/ui-v3/`，浏览入口 `design/ui-v3/index.html`。图稿采用公开示例，不读用户设备资料或屏幕。

## 窗口及任务流程

独立管理窗处理概览、布局、盘面与输入、连接与显示。标题栏C01–04是真实独立按钮定义，不用字符占位。布局页保留模块列表、舞台预览、上下文属性；每栏有明确定义的收起按钮和收起条C09。组展开C08与数据指示C23是不同控件，不能把HUD数据条画成可点击折叠条。

Ctrl+Alt+M与托盘“编辑布局”打开／完成同一编辑会话。进入时记录桌面原显隐；布局页在管理器操作，现场默认为不可交互虚影；现场模式C12为虚影／屏幕直接编辑／隐藏。完成操作结束手势、立即保存成功再结束会话；失败留在编辑页并显示错误与重试。关闭窗或Alt+F4走同一路径。最小化暂停管理预览、结束现场参考并恢复原桌面显隐；恢复窗口再次开启参考。最大化仅影响管理布局，不修改目标屏幕stage。

管理窗默认1440×960，最小960×640，标题栏56、导航区200、页工具条64、模块区248、属性区320、底操作栏64；画布区域自适应。1200以下可展开单侧属性抽屉；960宽两栏默认收起为44px侧条。顶栏和底栏不随内容滚动；核心操作不藏在末尾。设置页正文单列响应；所有字段和长文本可滚动阅读。

管理窗视图关闭后托盘与原HUD仍可运行。管理窗为独立、无原生owner的正常任务栏窗口，保持置顶，游戏前台时仍可操作；屏幕直接编辑时改为当前组件范围外的紧凑控制面板。现场虚影与隐藏模式不聚焦、鼠标穿透；屏幕直接编辑从进入时接收整屏鼠标，支持组件操作及空白框选，显式进入时一次交接焦点，整个正常编辑期间保持原生可激活资格；失焦不撤销下一次点击的激活资格。空位不足时的全屏编辑也可在首次点击前按Esc返回。HUD始终完整保留原位置和尺寸，管理器避让HUD；拖动中临时收起面板，松手后按最终范围落位，自动显示不抢焦点。无面板空位进入全屏编辑；Esc、编辑快捷键或空位返回条结束/返回。明确返回时恢复管理窗原状态和焦点。现场和管理预览共用同一编辑器手势、撤销和保存。虚影是同一HUD位置的临时替代表现。

## 程序员执行边界

以1.3.x `167cad4` 为功能基线，独立分支 `codex/racing-ui-refactor`，路径 `SimRacingOverlay-ui-refactor`。保留主树、轮盘树、MOZA算法研究树、全部stash/补丁/回放/基线，不整树覆盖。实施不提交或推送，必要本地运行入口更新属于本轮授权。

正常HUD保持唯一既有模型/遥测/场景准备/插值链。管理预览不得再次加载整套index计算链；仅消费现有绘制输出或已准备结果。现场虚影只消费布局几何与盘面材质；临时alpha与模式不写入用户布局，不影响OBS浏览器源。示例数据仅在管理器的明确示例展示中，现场不补造数值或事件。

具体采用受控同源 `window.open` 管理子窗，保持sandbox/contextIsolation等现有隔离设置；管理预览通过窄UI接口直接drawImage既有Canvas，不编码图像、不经主进程持续传整帧。固定本机管理页以外的弹窗不放行；管理窗显式focusable、独立任务栏身份且置顶、可调整大小，不继承现场窗的全屏/不聚焦设置。正常HUD画布继续原绘制，现场ghost时只隐藏其CSS显示，由纯UI虚影层替代；管理器仍可消费其正常绘制结果。关闭或最小化停止管理器复制帧，不改原HUD时钟。平台依据：[Electron window.open](https://www.electronjs.org/docs/latest/api/window-open)、[自定义窗口交互](https://www.electronjs.org/docs/latest/tutorial/custom-window-interactions)。

布局仍完整包含18模块及 `wheel.faceId/dashboardMode/buttonMaps`。操作复用layout v3；命中、绘制、选框、旋转同一变换；管理预览只是目标stage的等比缩放，留白从逆变换中扣除。拖动期间当前布局内存同步到现场；180ms合并持久化仍沿用原路径。一次手势一步历史，Escape/指针取消恢复起点；80步Undo/Redo包括盘面设置。锁定过滤、全锁禁用、多选混合、分轴禁用、导入保持stage、整体复位、屏外找回均保留。

管理窗为唯一可写UI会话，IPC仅允许该窗当前可信页面发出的明确UI动作；HUD仅接收当前布局／参考模式及返回已有显示帧。旧会话和销毁后回调不改当前状态。盘面下载/缓存及迟到结果隔离继续复用wheel-store与原资料；不能重写厂设映射。设备读取、候选阈值、轴归一化及绑定优先级保留，UI只加采用/取消与统一样式。

仪表显示方式与仪表页面独立：前者为布局的`wheel.dashboardMode`，后者沿用桌面配置`desktop.page`，不并入布局Undo。页面1仅嵌入仪表的挡位保持朝上（RPM/速度不作此反向旋转），页面2挡位随盘面转动；独立仪表继续不随盘面转动。页面1顶部转向位置标识及原显示条件保留。选择器复用C12；页面变化只更新原显示参数和必要显示缓存，不重载HUD或重建模型/worker，不重置布局、插值和时钟。

定义、页面、实现和交接以C/S/P ID关联。不能以一张控件表或核心图替代页面，也不能用页面省略为由删除核心功能。主负责人出图并自审设计，独立审查同时核对定义、完整输入和页面，批准后程序员开始受影响修改。

P13的简化组成图及P20子状态图用于说明信息和保留条件；生产程序始终消费原HUDCanvas，不按设计生成器的core()重写原有绘制。更多操作采用C24命令弹层；高级区用C19/C28；盘面映射与设备延续用C26/C27；紧凑抽屉用C25；自绘选择器使用共享C12定义，原生select的弹层不冒充可由CSS完整控制。

### 2026-11-05增量设计

C29–C33见UI-COMPONENTS：模块列表选择跟随、常驻整体移动、明确显隐/锁定、设置正文完整滚动、按盘面实际范围放大当前画面、布局快捷键重定义、可达的本段G峰值和完整退出。以上修正原“现场始终穿透”和桌面全景用于盘面预览的约定；算法指标及用户HUD布局不因预览fit改变。依据沿用UI-BASIS B1–B4；44px热区、8px预览余量等为工程值，不声称理论唯一取值。


运行补充：隐藏HUD的管理预览以同一原生窗透明供帧，不建立第二模型；现场显示不再扣除管理窗区域，预览读取同一个完整canvas。紧凑面板保留同一组模式、网格、吸附、撤销、列表、属性和完成入口，移除重复预览；列表与属性独立滚动。600×480为工程最小面板尺寸，按安全空白走廊尽量增高；盘面几何及旋转包络参与避让。已保存盘面在显式管理器打开和原生窗show时按实际需求恢复一次。取消只撤回本页未提交选择，当前使用名称绑定实际载入内容；冷启动失败支持明确重试。快捷键录入兼容KeyboardEvent.key与code的可用性，保存后才更新已绑定提示。


最小化/恢复补充：管理器保留标准Windows任务栏窗口和原生minimize/restore。最小化仅暂停交互和预览，保存直接编辑快照；iconic状态不写窗口位置、大小或最小尺寸。恢复继续原编辑模式和几何，真正退出正常现场编辑时才还原普通管理窗。原生暂停与页面编辑意图分开，暂停不触发退出并重新进入。
