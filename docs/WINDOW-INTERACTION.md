# 托盘与窗口交互

2026-11-07用户对安装版的修正要求：单击托盘打开管理窗；右键菜单不拖慢鼠标；管理窗在浏览和编辑期间均保持普通窗口层级；最小化完成编辑并保留HUD。

管理窗使用普通Windows层级。编辑虚影保持HUD的置顶叠加层级（`screen-saver`）和鼠标穿透，便于在其他窗口上方对照布局。现场直接编辑时，整屏HUD降为普通层级，避免它始终盖住管理面板；显式取得焦点时可以调整本应用两个普通窗口的前后顺序，不周期性抢前台。完成编辑后，HUD恢复作为游戏叠加层的层级和鼠标穿透。

布局编辑期间，最小化属于完成编辑的操作：结束手势、保存并退出编辑，保留HUD显示；恢复窗回到概览。其他页面最小化保留原页面与HUD显隐设置。保存失败不能静默丢弃编辑。原生窗口最小化和自绘按钮使用同一完成流程；窗口已处于iconic状态时不修改其bounds/minimumSize，正常几何待恢复后再处理。

## 鼠标转发的取舍

当前HUD只有进入明确编辑模式后才消费真实鼠标手势；穿透模式没有需要hover转发来激活的控件。因此去掉 `setIgnoreMouseEvents` 的 `forward:true`，保留穿透本身，编辑时正常接收鼠标。此改动不增加鼠标轮询或新的全局钩子。

与当前运行版本对应的 [Electron Windows源码](https://github.com/electron/electron/blob/v44.9.0/shell/browser/native_window_views_win.cc) 中，`SetForwardMouseMessages(true)` 注册 `WH_MOUSE_LL`，鼠标移动经过 `MouseHookProc`。这证明原选项会增加全局鼠标处理依赖；用户报告托盘菜单出现时鼠标卡顿，移除此处不需要的处理有直接机制依据。它不能单独证明现场全部卡顿都由该路径造成；不把源码分析写成已经量测的性能改善。
